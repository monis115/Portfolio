[ 01 ] the problem

Nine people, nine jobs, one application file

An education consultancy moves a student from first enquiry to a visa stamp. Along the way the same application file passes through an admission manager, an agent who sourced the student, an accountant chasing fees, a telex manager handling university correspondence, a university person, a visa manager, a documents person, the student themselves, and an admin over all of it.

Every one of them needs a different view of the same record, different permissions, and a different definition of "done". Get that wrong and either people see money they shouldn't, or they spend their day asking someone else to check something for them. The build is nine products sharing one spine.

[ 04 ] the parts that were actually hard

Money moves in more than one direction

The accountant's world isn't a payment button. Credit gets extended to agents, collection requests go out, funds get released against milestones, and liabilities sit on a dashboard accruing interest. That accrual runs on a scheduled job rather than being computed at read time — so the number is the same for everyone looking at it, and there's a row explaining how it got there.

Nine roles is an authorisation problem, not a UI problem

The dashboards differ, but the real work is server-side: every controller gates on role, and the front end mirrors it with route guards and an HTTP interceptor that attaches the token and handles the 401 centrally. The UI hides what you can't do; the API refuses it.

Documents are the product

Passports, offer letters, visa paperwork — the platform is a document pipeline wearing a CRM's clothes. Files live in S3, never on the application disk, so the container stays disposable and Beanstalk can replace it without losing anything.

The office has bad internet

Angular Service Worker + SSR wasn't a checkbox. Staff open the platform on phones in places with patchy signal; an installable app that renders on first byte and survives a dropped connection is the difference between the tool being used and being abandoned.

[ 05 ] what I'd change

With hindsight

  • Events over scheduled polling. Interest accrual and status notifications both run on timers. A small event bus would make the financial history append-only and easier to audit.
  • Contract tests. Nine roles against 35+ controllers is a big matrix to verify by hand. Generated API contracts would have caught drift between the Angular models and the DTOs earlier.
  • Split the document service. S3, iText and POI all hang off the main app. As a separate service it could scale on its own and stop PDF generation competing with request handling.
